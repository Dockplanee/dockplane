See workloads, health and resource state across every connected Docker host. Run, create, change and remove workloads through defined agent capabilities, with backend-enforced permissions and audit history. Each host runs one small service that connects outward to the control plane. No inbound management port has to be opened on a Docker host.
Each enrolled host uses its own agent identity and can be revoked independently. Operations such as restarting a container or reading logs use defined and validated actions. Backend-enforced permissions decide who may perform which operations. Restarting a container and removing one are separate grants. Security-relevant and infrastructure-changing actions are recorded with actor, target and result context.

Read the security model

Dockplane can check the public release listing and say whether something newer exists. It is off until an administrator turns it on, and nothing acts on the answer. Upgrade the control plane first, then the agents. An older agent keeps working while its protocol version is one the server accepts. The management lists and settings adapt to the space they are given, down to a stacked list below a tablet's width.
There is nothing to sign up for and no tenant to belong to. You install the control plane and it is yours. The architecture, permissions and agent trust model are documented instead of being hidden behind a remote service. What Dockplane manages is Docker and its immediate operational environment. It is not on its way to becoming a datacenter panel.
